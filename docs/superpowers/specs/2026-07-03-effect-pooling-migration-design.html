이펙트 풀링 마이그레이션 설계 — 서브 마이그레이션 ①

설계 스펙 승인 대기 선행: 풀링 코어(68b99482)·Addressables · 2026-07-03

1. 목적 요지

풀링 코어(Pool + PoolManager + IPoolableObject/PooledBehaviour)를 이펙트 계층의 실제 소비자에 연결한다. 이펙트는 지금 Instantiate/Destroy로 매번 생성·파괴되어 GC를 유발하며, "피격 이펙트 안 보임"의 출발점이었다.

이번 마이그레이션은 이펙트를 풀링하고, 코어를 PlayMode로 실검증하며, 유예된 게이트 D-5/6/7을 실제 프리팹으로 닫는 자리다.

2. 범위

이번 서브 마이그레이션 ① (이펙트)

  • AbilityEffect 엔티티: ProjectileEffect·OrbiterSetEffect·AreaZoneEffect(자가구동, Update로 거동)
  • 일회성 VFX: VfxPlayer.SpawnOneShot — 명중 VFX(hitVfxPrefab)·머즐 VFX(muzzlePrefab)
  • 스포너: IEffectSpawner/SimpleEffectSpawner → PoolManager 어댑터
  • 데이터: 능력 정의의 이펙트 프리팹 → Addressable
  • 예열: 능력 획득 시점 증분 예열
범위 밖(→ 서브 마이그레이션 ②): 액터(Monster/Tower) 풀링, EnemySpawner 자체 풀 흡수, ObjectPool<T> 제거. 소유 연쇄도 ②에서 — 이번엔 이펙트가 전부 자가반납(부모가 될 액터가 아직 풀링 안 됨).

3. 확정된 설계 결정 (브레인스토밍 합의)

#결정근거
A 풀 대상 프리팹 전부 Addressable 전환 원래 동기("강참조 상주 금지 → 약한참조")와 정합. 코어의 AssetReference 키와 일치.
ii 능력 획득 시 그 능력 이펙트만 증분 예열 낭비 0(가진 능력만). 예열 await는 카드 적용 흐름 → 전투 히칭 없음. 코어 동기 Get 유지.
b AbilityEffect·VfxPlayer가 PooledBehaviour 상속 계약 보일러플레이트(활성 토글 + 반납 배선) 중복 제거. 코어 재작업 없음.
— IEffectSpawner 유지 + 구현을 PoolManager 어댑터로 능력 정의(ctx.Effects) 변경 최소, 능력 로직을 풀 메커니즘에서 분리.
— 이펙트 자가반납(Dispose) 이펙트가 자기 종료 지점을 안다(Update). 코어가 반납 동작 주입(IReturnBindable).

4. 컴포넌트 설계

(1) 데이터 Addressable화 + 능력의 이펙트 자산 열거 수정 필요

능력이 자기 모든 이펙트 프리팹을 AssetReferenceGameObject로 들고, 한 곳(EffectAssets)에 모아 노출한다(예열 열거용).

Assets/Scripts/Systems/Abilities/AbilityData.cs (베이스에 추가)
// 이 능력이 (전이적으로) 사용하는 모든 풀링 프리팹. 예열 대상.
public virtual IEnumerable<AssetReferenceGameObject> EffectAssets
    => System.Array.Empty<AssetReferenceGameObject>();

각 능력 정의(ProjectileAbilityData 예)의 직접 프리팹 필드를 전환한다:

Assets/Scripts/Systems/Abilities/Definitions/ProjectileAbilityData.cs
▼ BEFORE
[SerializeField] private ProjectileEffect projectilePrefab;
[SerializeField] private GameObject muzzlePrefab;
// (명중 VFX 는 ProjectileEffect 프리팹 내부 hitVfxPrefab)
▼ AFTER
[SerializeField] private AssetReferenceGameObject projectileAsset;
[SerializeField] private AssetReferenceGameObject muzzleAsset;
[SerializeField] private AssetReferenceGameObject hitVfxAsset;   // 능력으로 끌어올림
// EffectAssets => projectileAsset·muzzleAsset·hitVfxAsset 중 non-null
명중 VFX 끌어올림: 명중 VFX가 지금 ProjectileEffect 프리팹의 SerializeField라 능력이 그 ref를 열거할 수 없다. hitVfxAsset을 능력으로 올리고, 발사 시 ProjectileEffect.Activate(...)에 넘겨 효과가 명중 순간 재생하게 한다.

(2) IEffectSpawner → PooledEffectSpawner (PoolManager 어댑터) 수정 필요

스포너는 엔티티 스폰과 일회성 VFX 재생 둘을 제공하고, 구현이 PoolManager를 감싼다.

Assets/Scripts/Systems/Abilities/Effects/IEffectSpawner.cs
public interface IEffectSpawner
{
    T Spawn<T>(AssetReferenceGameObject asset) where T : AbilityEffect;   // 엔티티
    void PlayOneShot(AssetReferenceGameObject asset, Vector3 pos, Quaternion rot); // 일회성
    void Release(AbilityEffect fx);   // = fx.Dispose()
}
  • Spawn<T> → poolManager.Get<T>(asset) + fx.Bind(this)(효과가 중첩 VFX 스폰하도록 스포너 주입)
  • PlayOneShot → Get<VfxPlayer>(asset) → transform 세팅 → vp.PlayThenReturn()
  • Release(fx) → fx.Dispose()
SimpleEffectSpawner(Instantiate/Destroy) 삭제. CoreAbilitySystem.Setup이 new PooledEffectSpawner(poolManager) 생성 → Setup 시그니처에 PoolManager 추가(합성 루트가 GameContext.PoolManager 전달).

(3) AbilityEffect : PooledBehaviour 수정 필요

Assets/Scripts/Systems/Abilities/Effects/AbilityEffect.cs
▼ BEFORE
public abstract class AbilityEffect : MonoBehaviour, IPoolable
{
    private IEffectSpawner spawner;
    public void Bind(IEffectSpawner s) { spawner = s; }
    protected void Release() { if (spawner != null) spawner.Release(this); else Destroy(gameObject); }
}
▼ AFTER
public abstract class AbilityEffect : PooledBehaviour
{
    private IEffectSpawner spawner;                     // 중첩 VFX 스폰용(반납 아님)
    public void Bind(IEffectSpawner s) => spawner = s;
    protected IEffectSpawner Spawner => spawner;
    protected void ReturnToPool() => Dispose();          // PooledBehaviour.Dispose = 풀 반납
}
  • 반납 경로: 기존 Release()(스포너 위임 파괴) → Dispose()(코어 주입 반납). 서브클래스 종료 호출부를 ReturnToPool()로 교체.
  • Bind는 반납이 아니라 중첩 일회성 VFX 스폰용으로 유지(예: ProjectileEffect의 명중 VFX).

(4) VfxPlayer : PooledBehaviour (일회성) 수정 필요

  • VFX 프리팹 루트에 VfxPlayer가 미리 부착돼야 한다(런타임 AddComponent 제거). Addressable 프리팹 준비 시 보장.
  • PlayThenReturn(): Play() → UniTask.Delay(ResolveDuration()) → Dispose(). 반납 시 OnDespawn에서 진행 중 delay 취소(재사용 인스턴스 오반납 방지).
  • EnsurePlay(지속 VFX, AreaZone/Orbiter 자식) 경로는 그대로 — 효과 엔티티와 함께 풀링. 단 AddComponent 폴백은 프리팹 사전 부착으로 대체.

(5) 예열 오케스트레이션 수정 필요

획득 예열(증분): AddAbility는 동기라 예열은 카드 적용 흐름에서 await.

Assets/Scripts/Systems/Cards/CardChoiceApplier.cs (async 경로로)
카드 선택 확정
  → await poolManager.WarmupAsync(data.EffectAssets, count)   // 있으면 스킵
  → core.AddAbility(data)
  → 전투 재개
  • 레벨업 카드(기존 능력)는 새 프리팹 없음 → WarmupAsync가 pools.ContainsKey로 no-op.
  • 스타터 예열: Setup의 스타터는 AddAbility를 안 거침 → 아레나 진입(첫 웨이브 전) 스타터 전부의 EffectAssets를 한 번 WarmupAsync로 예열.

(6) 게이트 구현 (D-5/6/7) — 실제 프리팹으로 닫기 필수

  • D-5: Get<T>의 pools[key] → TryGetValue 실패 시 명시 예외("WarmupAsync 예열 안 됨: {RuntimeKey}").
  • D-6: (1) Pool.Get의 GetComponent<IPoolableObject>() null → 프리팹명 담은 명시 예외. (2) Get<T>의 GetComponent<T>() null → 인스턴스 풀 반납 후 명시 예외(item==null 가드, 누수 방지). (3) 프리팹 루트에 poolable 컴포넌트 1개 규약.
  • D-7: "반납·Dispose 후 참조 사용 금지" 계약 주석. VfxPlayer delay 취소가 실사례 방어.

5. 데이터 흐름 (발사체 능력 예)

획득 → 발사 → 구동 → 종료
[획득] 카드 확정 → WarmupAsync(projectile·muzzle·hitVfx) → AddAbility → 재개
[발사] NotifyFireFrame → ProjectileAbilityData.Fire
        ├ ctx.Effects.Spawn<ProjectileEffect>(projectileAsset)  → Get + Bind + OnSpawn + Activate
        │    └ ProjectileEffect.Activate(..., hitVfxAsset)      // 명중 VFX ref 주입
        └ ctx.Effects.PlayOneShot(muzzleAsset, origin, rot)     → Get<VfxPlayer> + Play + 자동반납
[구동] ProjectileEffect.Update → 이동·명중 판정
        └ 명중 시: Spawner.PlayOneShot(hitVfxAsset, pos, rot)    // 명중 VFX
[종료] 관통 소진/사거리 초과 → ReturnToPool()(=Dispose) → OnDespawn → 풀 복귀

8. 구현 순서 (이펙트 내부 단계)

  1. 일회성 VFX 먼저(명중·머즐): VfxPlayer : PooledBehaviour + PlayOneShot/PlayThenReturn + muzzle/hitVfx Addressable화 + D-5/6/7 게이트 + PlayMode 명중 VFX 검증. → 원래 동기를 가장 먼저 닫고 코어 실검증.
  2. AbilityEffect 엔티티: Spawn<T> 경로 + 3개 서브클래스 자가반납 전환 + 나머지 능력 데이터 Addressable화.
  3. 스타터/획득 예열 배선 + SimpleEffectSpawner 제거.
