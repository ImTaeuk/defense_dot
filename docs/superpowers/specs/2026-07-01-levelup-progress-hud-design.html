레벨업 진척도 HUD 위젯 — 설계 제안서 (TASK-012 B-5)

설계 제안서 승인 대기 브레인스토밍 · 2026-07-01

1. 제보 요지

TASK-012 B-5 스펙: "다음 레벨업까지 남은 처치 수·진행 게이지를 HUD 위젯으로 노출(LevelModel 의 현재 kills·KillsToNextLevel 기반). 신규 UI 베이스(UIWidget<T>)로 LevelProgressWidget 추가, LevelModel 진행도를 ReactiveProperty 로 노출해 Presenter 가 Bind."

결론 한 줄: 기존 반응형 HUD 규격(모델 RP → Presenter Bind → Widget)을 그대로 재사용한다. 새 패턴 발명 없이, LevelModel 에만 진행도 RP 를 additive 하게 추가하면 된다.

2. 현재 동작 (재현 경로)

  1. 적 처치 → LevelModel.cs:22-35 RegisterKill() 가 Kills·Level·KillsToNextLevel 을 갱신
  2. 레벨업이 발생한 프레임에만 LevelModel.cs:34 의 OnLevelUp 이벤트 발화 → 카드 모달 표시
  3. HUD(ArenaHudView.cs)에는 골드·점수·라운드·시간·적 위젯만 존재 — 레벨/진척 표시 없음
  4. 처치가 진행돼도 "다음 레벨업까지 얼마나 남았는지"를 알리는 프레임 단위 통지 통로가 없음 (레벨업 순간의 OnLevelUp 뿐)

3. 근본 원인 — 구조적 공백

Assets/Scripts/Domain/Models/LevelModel.cs · RegisterKill() L22-35
public void RegisterKill()
{
    Kills++;
    bool leveled = false;
    while (Kills >= KillsToNextLevel) { /* ...레벨업... */ }

    if (leveled) OnLevelUp?.Invoke();   // ← 레벨업 순간에만 통지
}

LevelModel 은 아직 ReactiveProperty 로 전환되지 않은 유일한 HUD 모델이다. 처치마다 진행도(Kills/KillsToNextLevel)가 바뀌지만 이를 구독자에게 알릴 RP·이벤트가 없어, 게이지를 프레임 단위로 갱신할 수 없다. 이 공백을 메우는 것이 B-5 의 실질 작업이다.

4. 기획 요구사항 (추천안 · 승인 대기)

아래는 스펙 + 기존 컨벤션에서 도출한 추천 결정이다. 승인 또는 수정 시 확정된다.

  • Q1 표시 내용 — 추천 (a): 진행 게이지 + "남은 N"(다음 레벨까지 남은 처치) + 레벨 번호. (대안 b: "현재/필요" 7/12 형식, c: 게이지+레벨만)
  • Q2 시각 배치 — 추천 (a): 지금 현재 ArenaHUD 프리팹에 위젯 GameObject 를 MCP 로 배치해 즉시 Play 검증. (대안 b: 코드/배선만, GameObject 는 HUD 대체 작업 때 함께)
  • Q3 레벨업 펄스 연출 — 추천 제외 (YAGNI): 게이지 리셋만. 원하면 후속으로 추가.
  • 기존 Level·Kills·OnLevelUp API 는 그대로 유지 → 카드 모달(CardSelectionPresenter) 무영향.

통일감을 위해 프로젝트 내 두 레퍼런스에서 공통 사상을 차용한다.

(1) ModelStates.cs — LevelProgress DTO 추가 수정 필요

// WaveProgress / TimerState / HealthState / EnemyState 만 존재

/// <summary> 레벨 진척(레벨/누적 처치/필요/남은/비율) 표시 상태입니다. </summary>
public readonly struct LevelProgress
{
    public readonly int Level;
    public readonly int Kills;
    public readonly int KillsToNext;
    public readonly int Remaining;
    public readonly float Ratio;

    public LevelProgress(int level, int kills, int killsToNext)
    {
        Level = level;
        Kills = kills;
        KillsToNext = killsToNext;
        Remaining = killsToNext > 0 ? killsToNext - kills : 0;
        Ratio = killsToNext > 0 ? kills / (float)killsToNext : 0f;
    }
}

TimerState·EnemyState 와 동일하게 생성자에서 Ratio·Remaining 을 계산하는 불변 struct.

using DefenseDot.Domain;   // ReactiveProperty

public sealed class LevelModel : BaseModel
{
    private readonly System.Func<int, int> curve;
    private readonly ReactiveProperty<LevelProgress> progress;

    public int Level { get; private set; } = 1;
    // ... Kills / KillsToNextLevel / PendingLevelUps ...
    public IReadOnlyReactiveProperty<LevelProgress> Progress => progress;
    public event System.Action OnLevelUp;

    public LevelModel(System.Func<int, int> curve)
    {
        this.curve = curve;
        KillsToNextLevel = curve(Level);
        progress = new ReactiveProperty<LevelProgress>(Snapshot());
    }

    public void RegisterKill()
    {
        Kills++;
        while (Kills >= KillsToNextLevel) { /* ...레벨업... */ }
        progress.Value = Snapshot();   // 처치마다 진행도 통지
        if (leveled) OnLevelUp?.Invoke();
    }
    private LevelProgress Snapshot() => new LevelProgress(Level, Kills, KillsToNextLevel);
}
  • additive 변경 — 기존 Level/Kills/OnLevelUp 시그니처·의미 불변.
  • ReactiveProperty 는 동일 값 대입 시 통지 생략 → 처치마다 Snapshot() 이 바뀌므로 매 처치 통지된다.

모델 변경은 EditMode 로 자동 검증(TDD), 시각 표시는 Play 수동 검증.

1처치 누적 — 임계 미만 N회 처치Progress.Kills=N, Ratio=N/필요, Remaining=필요-N

5Play — 게이지 시각 (Q2-a)처치 시 채워지고 레벨업 시 리셋
