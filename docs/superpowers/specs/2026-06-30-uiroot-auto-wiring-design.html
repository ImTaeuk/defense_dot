UIRoot 자동 배선 재설계 — 확정 스펙

설계 스펙 확정 GameContext 주입 + 팩토리 리플렉션 · 2026-06-30
한 줄: UIRoot 는 List<UIView> 와 주입받은 GameContext 로 Presenter 를 자동 생성·배선한다. 새 UI 를 추가해도 UIRoot·팩토리·GameManager 는 무수정. 기존 베이스 계층(공통 메소드 분리)은 그대로 유지.

1. 목표 · 현재 문제

UIRoot 가 View 별 SerializeField + Inject 타입 분기로 성장하고, 미사용 필드(buildModalView·towerRoster)가 빈 슬롯으로 남으며, GameManager 가 UI 배선 세부에 개입(책임 누수)하는 문제를 해소한다.

선행: UI 베이스(UIObject·UIView·UIWidget·UIPresenter)·ReactiveProperty 이미 구현·커밋(49472631).

2. 설계 결정 (확정)

2.1 자동 배선 — View 순수 + Presenter 가 View 를 안다

  • View 는 Presenter 를 모른다(순수). 초안의 UIView<TPresenter>(역의존)는 폐기.
  • Presenter 가 View 를 안다 — 기존 UIPresenter<TView>. MVP 정석.
  • 팩토리가 UIPresenter<TView> 구현을 리플렉션 스캔해 {ViewType: PresenterType} 매핑 1회 구축 → switch 없음, View 증가에 무성장.

2.2 모델 접근 — GameContext 주입 (DI, 전역 아님)

  • GameContext: 모든 모델 홀드 묶음. static Instance 없이 주입.
  • Presenter 생성자 (TView view, GameContext ctx) — 생성자에서 필요한 모델만 추출해 구체 필드로 저장, ctx 는 미보관(Parameter Object).
  • 전역 가변상태 위험 없음. fake GameContext 주입으로 Presenter 테스트 가능.

2.3 책임 분배 — UIRoot 가 UI 초기화 전담

  • GameManager: 모델 생성 → GameContext 구성 → uiRoot.Inject(ctx) 한 번 위임(UI 세부 모름).
  • UIRoot: Inject(ctx) 안에서 팩토리 생성 + List<UIView> 순회 배선·Initialize, OnDestroy 일괄 Dispose.

2.4 베이스 계층 — 그대로 유지 (공통 분리)

베이스분리된 공통
UIObjectRectTransform 캐싱 · Depth
UIViewShow/Hide/OnShow/OnShown 생명주기
UIWidget<T>SetData 표시 계약
UIPresenter<TView>Initialize/Dispose/재진입가드 + Bind(구독+초기값+토큰해제+OnShow 재반영)
각 Presenter 는 OnInitialize 에서 Bind(...) 한 줄씩, 각 View 는 위젯 조립·Apply* 위임만. 중복 0.

2.5 범위 — UIRoot 참조 View 전부 UIView 이전

ArenaHudView(완료) + CardSelectionView·GameResultView·TowerBuildModalView → UIView. 한 List<UIView> 통일. 미사용 필드 자연 소멸.

3. 핵심 코드 골자

Presenter — (TView, GameContext) 생성자에서 추출 + OnInitialize Bind
public sealed class ArenaHudPresenter : UIPresenter<ArenaHudView>
{
    private readonly EconomyModel economy;
    private readonly ScoreModel score;
    // … wave / timer / enemyCapacity

    public ArenaHudPresenter(ArenaHudView view, GameContext ctx) : base(view)
    {
        economy = ctx.Economy;  score = ctx.Score;  // 필요한 것만 추출
        wave = ctx.Wave;  timer = ctx.Timer;  enemyCapacity = ctx.EnemyCapacity;
    }

    protected override void OnInitialize()
    {
        Bind(economy.Gold, view.ApplyGold);   // 공통 Bind 는 베이스
        Bind(score.Score,  view.ApplyScore);
        // … wave.Progress / timer.Time / wave.RemainingEnemies
    }
}
UIPresenterFactory (POCO) — 리플렉션 스캔, switch 없음
public sealed class UIPresenterFactory
{
    private readonly GameContext ctx;
    private readonly Dictionary<Type, Type> map;   // {ViewType: PresenterType}

    public UIPresenterFactory(GameContext ctx)
    { this.ctx = ctx; map = BuildViewToPresenterMap(); }

    public IPresenter Create(UIView view)
    {
        if (view == null) return null;
        if (!map.TryGetValue(view.GetType(), out Type pt)) return null;
        return (IPresenter)Activator.CreateInstance(pt, view, ctx);
    }
}
UIRoot — ctx 받아 factory 생성·배선 전담 / GameManager 위임
// UIRoot
public void Inject(GameContext ctx)
{
    var factory = new UIPresenterFactory(ctx);
    foreach (UIView view in views)
    {
        IPresenter p = factory.Create(view);
        if (p == null) continue;
        presenters.Add(p); p.Initialize();
    }
}

// GameManager.Start
var ctx = new GameContext(Economy, Wave, Score, RoundTimer, Core, Flow, Level, capacity, ...);
uiRoot.Inject(ctx);
