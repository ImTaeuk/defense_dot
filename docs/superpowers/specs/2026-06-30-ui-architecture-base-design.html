UI 아키텍처 베이스 계층 재설계

설계 문서 승인 · 4-렌즈 검증 반영 범위: 베이스 신설 + HUD 전체 이전 · 2026-06-30

1. 제보 요지

"여태 UI 구조에 Base를 안 두고 온 게 너무 후회되네. 지금 코드를 보니까 하수 바이브코더가 짠 느낌이 강해. 전체 구조를 내가 짜서 전달할게. 부족한 점이 있으면 피드백하고 한번 고쳐나가보자."

결론: 흩어진 UI 베이스를 UIObject 정점으로 통일하고 Model 통지·바인딩을 표준화한다. 단, 적대 검증 결과 사용자 초안의 두 결정(전역 레지스트리·RP 전면 래핑)은 안티패턴이라 조정했다.

2. 현재 동작 (혼재 진단)

이미 부분 베이스가 있으나 통일이 안 됨 — 같은 역할을 두 방식으로 구현 중이다.

영역통일된 곳벗어난 곳
Presenter 베이스BasePresenter<TView,TModel> (ArenaHud·HUD)IPresenter 직접 (Card·Result·TowerBuild)
View 베이스HudRoot : MonoBehaviour, IView맨 MonoBehaviour (Card·Result·Gold·Health·Round)
Widget/View 혼동—GoldView·HealthView·EnemyCountView·RoundView는 사실상 위젯인데 View로 명명
BaseModel—UI.BaseModel(빈) + Domain.Models.BaseModel(SetField) 2개 공존

3. 근본 원인

Assets/Scripts/UI/Presenters/ArenaHudPresenter.cs · HandleGoldChanged L73-77
private void HandleGoldChanged(int gold)
{
    model.CurrentGold = gold;   // ← 도메인 Economy가 이미 든 값을 또 저장(이중 캐싱)
    view.SetGold(gold);
}

ArenaHudModel/HUDModel은 도메인 Model 값을 또 저장하는 이중 캐싱 중간 Model이다. 베이스 부재로 위젯·뷰·프레젠터가 제각각 구현됐고, BaseModel이 둘로 갈려 있다. 이 모든 게 "하수 바이브코더 느낌"의 실체다.

4. 기획 요구사항 (사용자 확정)

  • UIObject 정점 — 아래 UIWidget/UIWidget<T>·UIView·UIPresenter<T:UIView>
  • Presenter는 UIObject 밖 별도 계층, View만 제네릭 (Model은 필드 직접)
  • Model 전역 접근 → 검증 후 기존 constructor-DI 유지로 확정
  • Model 필드 = 자체 경량 ReactiveProperty<T>, 단일 스칼라 전용 + 다중 스칼라는 별도 struct 래퍼
  • Presenter가 RP를 위젯에 즉시 반영하는 바인딩 (AsyncBinding = RP의 오기, 즉시 반영)
  • 범위 = 베이스 + HUD 전체 이전

전역 레지스트리를 버리고 이미 코드에 존재하는 두 패턴을 표준으로 승격한다.

6. 해결 방안 — 설계

(1) Model 전역 접근 — 레지스트리 폐기 검증 반려

▼ BEFORE (사용자 초안)
public static class Models {              // Service Locator
    public static EconomyModel Economy { get; private set; }
}
// 사용: Bind(Models.Economy.Gold, ...)  // 전역 숨은 의존
▼ AFTER (확정)
// 레지스트리 없음. GameManager가 생성 → UIRoot가 Presenter에 주입.
public sealed class GoldPresenter : UIPresenter<GoldView> {
    private readonly EconomyModel economy;          // 생성자 주입
    public override void Initialize() => Bind(economy.Gold, view.GoldWidget.Set);
}
  • 전역 정적 상태·숨은 의존성 제거 — 기존 DI 우수성 보존
  • LevelModel(curve)·Economy.Initialize(startGold) 생성 인자, EditMode new 격리 테스트 그대로 유지

(2) ReactiveProperty — 단일 스칼라 + struct 래퍼 신규

Domain/Models/ReactiveProperty.cs (신규) · 단일 스칼라 전용
▼ AFTER
public sealed class ReactiveProperty<T> : IReadOnlyReactiveProperty<T> {
    private T value;
    public event System.Action<T> OnChanged;
    public T Value { get; internal set; }   // 쓰기 internal — 모델 메서드만
    public void ForceNotify();              // equality 우회(초기/재시작)
}
// 단일: Economy.Gold = RP<int>.  다값: RP<WaveProgress{current,total}> (원자 통지)
다인자(OnWaveChanged(int,int))·파생(OnHealthChanged(ratio))은 struct로 묶어 비율 계산 중간상태 깜빡임을 막는다. 신호형(OnLevelUp)은 RP 아님(event 유지).

(3) UIPresenter.Bind — 토큰·OnShow 재반영 신규

UI/Base/UIPresenter.cs (신규)
▼ AFTER
protected void Bind<V>(IReadOnlyReactiveProperty<V> src, System.Action<V> sink) {
    sink(src.Value);                         // 초기값 1회
    src.OnChanged += sink;                    // 구독
    unbinders.Add(() => src.OnChanged -= sink); // Dispose 시 일괄 해제(토큰)
}
// OnShow() 시점에 바인딩값 재반영 → InactiveOnStart/풀링 stale 방지
