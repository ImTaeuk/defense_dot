API 레퍼런스 구현·검증 완료 (EditMode 136/136) TASK-013 · Mono 전용 · 2026-07-03

0. 설계 한눈에

MonoBehaviour(프리팹) 을 재사용하는 풀링 인프라입니다. 매 스폰마다 Instantiate/Destroy 하던 것을 풀에서 빌려/돌려주는 방식으로 바꾸고, 프리팹은 Addressables 약한참조로 로드합니다.

  • 클래스는 딱 둘 — Pool(풀 자체) + PoolManager(여러 풀을 부리는 조율자). 풀 위에 뭘 얹은 게 아니라, 매니저는 "여러 풀·소유 연쇄·뿌리 절단·비동기 로드"라는 별개 요구를 담당한다.
  • Mono 전용 — 풀은 프리팹을 직접 Instantiate/Destroy. 제네릭·팩토리 계층 없음.
  • 계약 인터페이스 — 리셋(IPoolableObject) · 활성+알림(IActivatable) · 반납 배선(internal IReturnBindable).
  • 반납 = 파괴 아님 — Dispose() 는 "풀로 반납". 자가(객체가 스스로)·외부(소유자가 호출) 둘 다 같은 Dispose/Return 으로.
  • PooledBehaviour — 선택적 편의 베이스(강제 아님). 계약 보일러플레이트를 담아 상속만으로 획득.
실제 게임 코드가 만지는 건 대부분 PoolManager(4) 와, 풀 대상이 상속할 PooledBehaviour(3) 또는 계약 인터페이스(1) 뿐입니다.

1. 계약 인터페이스

IPoolableObject 인터페이스

용도. 풀이 재사용하는 객체의 계약입니다. 재사용 시 자기 상태를 초기화하고, Dispose() 는 파괴가 아니라 "풀 반납"을 뜻합니다(실제 반납 동작은 PoolManager 가 주입).

Assets/Scripts/Core/Pooling/IPoolableObject.cs
public interface IPoolableObject : IActivatable, System.IDisposable
{
    void OnSpawn();
    void OnDespawn();
}
API의미 · 용도
void OnSpawn()풀에서 꺼내 재사용할 때 — 이전 사용 흔적(타깃·타이머 등) 초기화.
void OnDespawn()풀로 반납되기 직전 — 참조·상태 정리.
void Dispose() IDisposable"반납" 트리거. 자가(내부) · 외부(소유자) 둘 다 호출. 실제 동작은 매니저가 주입, using 도 가능.
풀은 대상을 항상 켜고/끄므로 IActivatable 을 포함한다(: IActivatable). 풀 대상은 두 계약을 모두 구현해야 하며 컴파일이 강제한다. (적대적 리뷰 반영 — 분리 시 hard-cast InvalidCastException 위험 제거)

IActivatable 인터페이스

용도. 켜기/끄기 상태와 활성 전이 알림. 외부(연출·사운드 등)가 객체 내부를 몰라도 켜진/꺼진 순간을 구독할 수 있습니다.

Assets/Scripts/Core/Pooling/IPoolableObject.cs
public interface IActivatable
{
    bool IsActive { get; }
    void Activate();
    void Deactivate();
    event System.Action OnActivated;
    event System.Action OnDeactivated;
}
API의미 · 용도
bool IsActive현재 활성 여부.
Activate() / Deactivate()켜기 / 끄기. 풀의 Get/Return 이 호출.
OnActivated / OnDeactivated켜짐 / 꺼짐 직후 발화(외부 관찰자용). 구독자 없어도 비용 없음.

IReturnBindable internal 인터페이스

용도. PoolManager 가 객체에 "반납하는 법"(Dispose 시 어느 풀로 돌아갈지)을 주입하기 위한 내부 계약입니다. 덕분에 객체는 자기가 어느 풀 소속인지 몰라도 됩니다.

Assets/Scripts/Core/Pooling/IPoolableObject.cs (internal)
internal interface IReturnBindable
{
    void BindReturn(System.Action returnAction);
}
API의미 · 용도
BindReturn(Action)반납 동작 주입. PoolManager.Retain 이 Get 시점에 호출(외부 비공개). 객체는 Action 하나만 품고, Dispose 시 누른다.

2. Pool — 풀 그 자체 (한 클래스)

용도. 프리팹 하나를 재사용하는 풀입니다. 놀고 있으면 큐에서 꺼내고, 없으면 Instantiate 합니다. 이론적 "풀링"은 이 한 클래스로 완결됩니다(제네릭·팩토리 없음).

Assets/Scripts/Core/Pooling/Pool.cs
public sealed class Pool
{
    public Pool(GameObject prefab);
}
API의미 · 용도
Pool(GameObject prefab)재사용할 프리팹 주입.
GameObject Get()재사용 인스턴스를 켜서 내줌(없으면 Instantiate). 순서: OnSpawn(리셋) → Activate(켜기).
void Return(GameObject)인스턴스를 끄고 큐로 되돌림. 순서: Deactivate(끄기) → OnDespawn(정리).
void Clear()큐에 남은 인스턴스를 파괴(풀 폐기 시 GameObject 누수 방지). 런타임=Destroy/에디트=DestroyImmediate.
풀은 대상의 구체 타입을 모른다 — Get/Return 은 GetComponent<IPoolableObject>/IActivatable 로 계약에만 의존한다. 매니저 없이 이 풀만 직접 써도 된다.

3. PooledBehaviour — 선택적 편의 베이스

용도. 풀링되는 MonoBehaviour 를 위한 선택적 베이스입니다. 상속만으로 활성·반납 계약을 얻고, 하위는 필요한 리셋만 오버라이드합니다. 강제가 아님 — 자기 베이스가 있는 타입(효과·액터)은 계약 인터페이스를 직접 구현해도 됩니다.

Assets/Scripts/Core/Pooling/PooledBehaviour.cs
public abstract class PooledBehaviour
    : MonoBehaviour, IPoolableObject, IActivatable, IReturnBindable
API의미 · 용도
bool IsActivegameObject.activeSelf.
Activate() / Deactivate()SetActive + 이벤트 발화.
virtual OnSpawn() / OnDespawn()하위가 리셋만 오버라이드(기본 no-op).
void Dispose()주입된 반납 동작 실행 → 풀로 반납.
Mono 전용이라 풀 대상은 결국 이 베이스 또는 계약 구현 컴포넌트다. (POCO 를 풀링하려면 이 인프라가 아니라 별도 큐를 쓰면 된다.)

4. PoolManager — 조율자

용도. 프리팹 풀들을 총괄합니다. 레벨 진입 시 예열하고, 대여 장부·소유 연쇄·뿌리 절단으로 누수 없이 정리합니다. GameContext 가 보유·주입합니다(전역 static 아님).

Assets/Scripts/Core/Pooling/PoolManager.cs
public sealed class PoolManager : System.IDisposable
{
    public PoolManager(AssetLoader assetLoader);
}
API의미 · 용도
UniTask WarmupAsync(
  IEnumerable<EffectEntry> entries,
  int count = 3)		 이펙트 프리팹을 로드하고 각 풀에 count 개를 미리 채운다. 레벨 시작 1회. 예열 개수는 데이터가 아니라 호출자가 결정(기본 3).
T Get<T>(
  AssetReference reference,
  object owner = null)
  where T : Component, IPoolableObject		 예열된 풀에서 동기로 꺼냄. owner 를 주면 소유 자식으로 등록(부모 반납 시 함께 회수).
void Return(object obj)풀로 반납. 소유 자식부터 연쇄 회수, 이미 반납된 것은 무시(이중 반납 가드).
void Dispose()밖에 나간 것 전량 회수 + 풀 정리(GameObject 파괴) + 에셋 해제. 뿌리 절단 = 누수 안전망.
internal void Retain(
  item, pool, owner)		방금 꺼낸 객체를 대여 장부에 등록(반납 배선 주입 + 소유 등록). RefCount 계열의 "retain(붙잡다)". 테스트 seam 겸용.
장부가 왜 필요한가 — "밖에 빌려나간 목록"이 있어야 ① Dispose 때 남은 것 전량 회수(누수 0) ② 부모→자식 소유 연쇄 회수 ③ 이중 반납 가드 + 되돌릴 풀 조회 가 가능하다.

타이밍은 도메인이, 메커니즘은 매니저가. "언제 반납하나"는 구체 타입이 정한다(자기 끝나는 지점에서 Dispose() 호출). "어떻게 회수/정리하나"는 매니저가 맡는다.

5. 데이터 — EffectType / EffectEntry

용도. 이펙트 용도 분류 + "용도 → Addressables 프리팹" 매핑입니다. 스포너/아레나 데이터가 이 목록을 들고 WarmupAsync 에 넘깁니다.

Assets/Scripts/Core/Pooling/EffectType.cs
public enum EffectType { Hit, Muzzle, Cast, Death }

[System.Serializable]
public struct EffectEntry
{
    public EffectType type;
    public AssetReferenceGameObject asset;
}
예열 개수(count) 는 여기 없다 — "데이터가 자기 개수를 정하는 건 아이러니"라, 예열 주체인 WarmupAsync 호출자가 결정한다.

6. 사용 흐름 (end-to-end)

사용 예시 (개념)
// 1) 레벨 진입(로딩) 시 1회 — 프리팹 로드 + 풀에 3개씩 예열
await ctx.Pooling.WarmupAsync(arenaData.effects, count: 3);

// 2) 전투 중 — 동기, 즉시 획득
HitEffect fx = ctx.Pooling.Get<HitEffect>(hitEffectRef, owner: monster);

// 3) 이펙트가 끝나면 — 스스로 반납(외부 배선 없이 자기 코드에서)
//    class HitEffect : PooledBehaviour { void OnAnimationEnd() => Dispose(); }

// 4) 레벨 종료 — 남은 것 전량 회수 + 프리팹 파괴 + 에셋 해제
ctx.Pooling.Dispose();

owner: monster 로 묶었으니 몬스터가 죽어 반납되면 이펙트도 자동 회수된다. 누구도 명시적으로 안 돌려줘도 Dispose 가 마지막 안전망으로 전부 거둔다.

7. 이전(초안) 대비 변경 요약

항목변경
계약 인터페이스IPoolable → IPoolableObject : IDisposable. 리셋+반납을 한 계약으로.
풀Pool<T> 제네릭 + IPoolFactory + PrefabFactory → 비제네릭 Pool 한 클래스(프리팹 직접 Instantiate/Destroy). 비제네릭 IPool seam 도 소거.
POCO 경로삭제 — Get(object)·PocoFactory·PooledObject 제거. Mono 전용.
풀 레지스트리이질 키 혼재 → RuntimeKey 단일 키 (Dictionary<object, Pool> 동종).
예열 진입점PoolAsync → WarmupAsync(count = 3). 인스턴스 예열 추가.
장부 등록Track → Retain(RefCount 계열).
폐기 정리Pool.Clear() 가 GameObject 파괴 → 프리팹 누수 해결.
PooledBehaviour폐기하려다 선택적 베이스로 유지 — 테스트 더블·신규 타입에 필요. 강제는 아님.
이 문서는 구현·검증 완료(EditMode 136/136) 기준이다. 마이그레이션(효과·액터 14곳을 이 계약으로 전환, EnemySpawner·VfxPlayer 연결)은 후속 계획으로 처리한다.
