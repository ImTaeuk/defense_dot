디버그 공격 타입 구현 제안서 — 단일 · 범위 · 투사체 (A-1~A-4)

제안서 검증 완료 · 구현 대기 4차원 멀티에이전트 검증 반영 · 2026-06-08

1. 제안 요지

플레이 루프가 실제로 도는지 런타임에 눈으로 검증하기 위해, 타워에 공격 타입 3종(단일/범위/투사체)을 throwaway 디버그로 붙인다. 인스펙터 토글로 플레이 중 타입을 하나씩 add/remove(능력 카드 스택 느낌)하며 루프를 확인한다. 전략 계약(IAttackBehavior/AttackContext)과 TargetFinder.FindAllInRange는 이미 구현·커밋됨 — 본 제안은 그 위에 얹는 A-1~A-4를 다룬다.

검증 결론: A-1·A-2 는 4차원(로직·Unity API·컨벤션·YAGNI) 전부 통과 = 즉시 구현 가능. A-3 는 투사체 관통이 실제로 작동 안 함(critical) → 수정본 제안. A-4 는 using 2건 추가가 컴파일 필수.

2. 현재 동작 (A-1~A-4 가 얹히는 경로)

  1. 매 프레임 TowerActor.cs:77-89 Update() 가 IsTargetValid() 검사 → 유효 시 UpdateCombat, 아니면 SearchTarget() 으로 최근접 적 재탐색
  2. CombatLogic.cs:30-44 Tick() 가 쿨다운 경과 시 PerformAttack() 호출
  3. 현재 TowerActor.cs:42-55 PerformAttack() 는 currentTarget 1체에 즉시 TakeDamage(attackDamage) — 단일 공격 1종만 존재
  4. 적 처치 → EnemySpawner.cs:121-125 보상 → 골드(HUD), 적 코어 도달 → 코어 체력 감소
선행 완료(커밋됨): TargetFinder.FindAllInRange (1a58371) · AttackContext / IAttackBehavior (ce06173). 이 3개는 재작성 금지.

3. 검증으로 드러난 핵심 이슈 (A-3 투사체 관통)

계획 원안의 DebugProjectile 는 첫 명중 후 target = null 로 두고 직진시키는데, 정밀 추적 결과 관통이 실질적으로 작동하지 않는다.

계획 원안 · DebugProjectile.Update() (검증 대상)
    Vector3 aim = (target != null && target.IsActive)
        ? target.Position
        : transform.position + transform.forward;   // 회전 미설정 → 항상 월드 +Z
    transform.position = Vector3.MoveTowards(transform.position, aim, speed * Time.deltaTime);

    if (target != null && target.IsActive && ...sqrMagnitude < 0.09f)
    {
        if (target is IDamageable d) d.TakeDamage(damage);
        pierceRemaining--;
        if (pierceRemaining <= 0) { Destroy(gameObject); return; }
        target = null;   // 이후 명중 판정이 target!=null 가드에 막힘 → 2번째 적 불가
    }

① 첫 명중 후 target == null 이 되면 명중 판정 자체가 target != null 가드에 막혀 2번째 적을 절대 타격할 수 없다. ② 콜라이더도 제거되어 물리 충돌도 없다. ③ transform.forward 는 회전 미설정이라 항상 월드 +Z 라 잔여 비행이 발사 궤적과 무관하다. 결과적으로 PierceMax=3 은 죽은 파라미터이며 "최대 3관통" 문구와 불일치한다.

4. 확정 요구사항 (브레인스토밍)

  • 공격 타입 3종(단일 즉시 / 범위 즉시 / 투사체)을 디버그 전용으로 구현 — 실제 VFX·파티클은 HD2D 이후
  • 런타임에 타워에 타입을 하나씩 add/remove(인스펙터 토글) — "능력 카드 스택" 느낌
  • 아키텍처: 기존 IMovementStrategy(이동)와 동형의 IAttackBehavior 전략 패턴
  • TowerData 불변 · 재화/도메인/HUD 불변 · 9개 EditMode 회귀 0
  • 실제 능력 카드 시스템 구현 시 본 3타입은 삭제(throwaway 전제, 전 코드 // DEBUG 표식)

5. 설계 원칙 — 컨벤션 정렬

통일감을 위해 프로젝트 내 기존 두 패턴에서 사상을 차용했다.

레퍼런스위치차용 포인트
이동 전략 패턴 GridDefenseMode.cs:41-47, PathFollowerLogic.cs 전략 인터페이스 주입 — 모드/액터가 IMovementStrategy 구현체를 주입받아 교체. 공격도 동형 IAttackBehavior 로 둔다
적 질의 패턴 TargetFinder.cs:24-46 FindNearest, EnemyRegistry.cs registry 순회 + 제곱거리 비교 — 사거리 내 적 선정. FindAllInRange(범위)·관통 재질의가 이 패턴을 그대로 재사용
결합 결론: 공격을 behavior 단위로 분리(전략 패턴)하되, 대상 선정은 기존 TargetFinder(FindNearest/FindAllInRange)에 위임한다. 새 개념 도입 없이 기존 2패턴의 합으로 구성 → throwaway 삭제 시 흔적 최소.

6. 해결 방안 — A-1 ~ A-4

(A-1) SingleTargetAttack — 신규 신규 파일 검증 ready

Assets/Scripts/Systems/Tower/Debug/SingleTargetAttack.cs
▼ 신규
// DEBUG: 공격 타입 테스트용 — 실제 능력 시스템 구현 시 삭제
using UnityEngine;
using DefenseDot.Core;

namespace DefenseDot.Systems.Tower.Debugging
{
    /// <summary> 최근접 적 1체에 즉시 데미지 + 타워→타겟 라인. (DEBUG) </summary>
    public class SingleTargetAttack : IAttackBehavior
    {
        public void Execute(in AttackContext ctx)
        {
            if (ctx.Finder == null || ctx.Data == null) return;
            ITargetable target = ctx.Finder.FindNearest(ctx.Origin, ctx.Data.attackRange);
            if (target == null) return;
            if (target is IDamageable damageable) damageable.TakeDamage(ctx.Data.attackDamage);
            UnityEngine.Debug.DrawLine(ctx.Origin, target.Position, Color.cyan, 0.08f);
        }
    }
}
검증: 기존 PerformAttack 의 단일타겟 로직(FindNearest 캐스트 후 IDamageable.TakeDamage)과 의미상 동치. MonsterActor 가 IDamageable·ITargetable 모두 구현 → 캐스팅 성립. 변경 없이 채택.

(A-2) AoeAttack — 신규 신규 파일 검증 ready

Assets/Scripts/Systems/Tower/Debug/AoeAttack.cs
▼ 신규
// DEBUG ...
using System.Collections.Generic;
using UnityEngine;
using UnityEngine.Pool;
using DefenseDot.Core;

namespace DefenseDot.Systems.Tower.Debugging
{
    /// <summary> 반경(=attackRange) 내 전체 적에 즉시 데미지 + 원 비주얼. (DEBUG) </summary>
    public class AoeAttack : IAttackBehavior
    {
        public void Execute(in AttackContext ctx)
        {
            if (ctx.Finder == null || ctx.Data == null) return;
            float radius = ctx.Data.attackRange;
            List<ITargetable> hits = ListPool<ITargetable>.Get();
            ctx.Finder.FindAllInRange(ctx.Origin, radius, hits);
            for (int i = 0; i < hits.Count; i++)
                if (hits[i] is IDamageable damageable) damageable.TakeDamage(ctx.Data.attackDamage);
            ListPool<ITargetable>.Release(hits);
            DrawCircle(ctx.Origin, radius, Color.magenta);   // 세그먼트 라인 24개
        }
        // private static void DrawCircle(...) — 원안 그대로
    }
}
검증: ListPool Get/Release 쌍 정확, 스냅샷 리스트 순회라 순회 중 적 사망(registry 변경)에 안전(IndexOutOfRange 없음), 한 Execute 내 동일 적 1회만 타격 = 중복 피해 없음. CollectionPool 컨벤션 준수. EditMode 테스트 AoeAttack_KillsEnemiesInRange_SparesOutside 동반.

신규 헬퍼 — NextNearestUnhit()
    private ITargetable NextNearestUnhit()
    {
        List<ITargetable> cands = ListPool<ITargetable>.Get();
        finder.FindAllInRange(transform.position, range, cands);
        ITargetable best = null; float bestSqr = float.MaxValue;
        for (int i = 0; i < cands.Count; i++)
        {
            ITargetable c = cands[i];
            if (hit.Contains(c)) continue;
            float d = (c.Position - transform.position).sqrMagnitude;
            if (d < bestSqr) { bestSqr = d; best = c; }
        }
        ListPool<ITargetable>.Release(cands);
        return best;
    }

핵심 변경 포인트

  • PierceMax=3 이 실제로 동작 — 최대 3체를 차례로 관통 타격
  • HashSet<ITargetable> hit 로 동일 적 재타격 방지, FindAllInRange 재사용(레퍼런스 ②)
  • Spawn 시 transform.forward 를 발사 방향으로 설정 → 잔여 비행이 자연스러움
  • 대안(보류 가능): 시각 검증만 필요하면 PierceMax=1 + 주석 "관통 미구현"으로 단순화. 단 이 경우 계획 V3 "최대 3관통" 문구도 함께 수정

using UnityEngine;
using DefenseDot.Core;
using DefenseDot.Data;
using DefenseDot.Systems.Tower.Debugging;          // ★ 필수
...
    // DEBUG 토글 + behavior 보유
    [Header("DEBUG Attack Toggles")]
    [SerializeField] private bool debugSingle = true;
    [SerializeField] private bool debugAoe = false;
    [SerializeField] private bool debugProjectile = false;
    private readonly IAttackBehavior singleBehavior = new SingleTargetAttack();
    private readonly IAttackBehavior aoeBehavior = new AoeAttack();
    private readonly IAttackBehavior projectileBehavior = new ProjectileAttack();
    private readonly List<IAttackBehavior> activeBehaviors = new List<IAttackBehavior>();
...
public void PerformAttack()
{
    if (currentTarget == null || !currentTarget.IsActive) { SetState(ActorState.Idle); return; }
    SetState(ActorState.Attacking);
    activeBehaviors.Clear();
    if (debugSingle) activeBehaviors.Add(singleBehavior);
    if (debugAoe) activeBehaviors.Add(aoeBehavior);
    if (debugProjectile) activeBehaviors.Add(projectileBehavior);
    if (activeBehaviors.Count == 0) return;
    AttackContext ctx = new AttackContext(this, Position, targetFinder, data);
    for (int i = 0; i < activeBehaviors.Count; i++) activeBehaviors[i].Execute(in ctx);
}

  • Update/IsTargetValid/SearchTarget/currentTarget 게이팅은 불변 — "사거리 내 적 존재" 트리거 역할 유지
  • AttackContext(this, Position, targetFinder, data) — 접근성 전부 유효(검증 confirm)
  • 선택(보류 가능): list 재구성 대신 if(debugSingle) singleBehavior.Execute(in ctx) 직접 3분기로 더 단순화 가능(throwaway라 현행도 무방)
