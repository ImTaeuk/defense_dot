인게임 플레이 루프 완성도 감사 — 배선은 완성, 게임은 미완성

분석 수정 미착수 분석 완료 · 2026-07-19 · TASK-020

1. 제보 요지

사용자 질의: "게임 내 플레이 루프는 정확히 완성 된게 맞아?"

이어진 사용자 판단: "작동만 가능한 상태이다. 라는거구나."

배경 — 직전까지 계보(합성) 시스템에 대해 "실 플레이 검증 완료"를 보고했다. 그 보고의 실제 범위가 "루프 완성"인지 "기능 작동"인지 확인이 필요했다. 문서(docs/) 주장을 근거에서 배제하고 코드·씬·데이터만으로 전수 감사했다.

결론: 사용자 판단이 정확하다. 배선(연결)은 어디서도 끊기지 않으나, 승패 판정·전투 밸런스·성장 반영이라는 규칙 층이 비어 있어 플레이 경험으로 성립하지 않는다.

3-4. isSpawning 누수 (잠복)

catch의 return이 플래그 복원 앞에서 반환한다.

Assets/Scripts/Systems/Enemy/EnemySpawner.cs:140-161
        private async UniTask SpawnWaveRoutineAsync(WaveData wave, CancellationToken token)
        {
            isSpawning = true;
            try { ... await UniTask.Delay(...); ... }
            catch (System.OperationCanceledException)
            {
                return;   // ★ 여기서 이탈 — 아래 복원에 도달 못 함
            }

            isSpawning = false;   // 취소 경로에서는 실행되지 않음
            CheckWaveComplete();
        }
귀결: 스폰 도중 라운드가 전환(취소)되면 플래그가 영구 true. EnemySpawner.cs:220,236의 !isSpawning 가드가 영구 거짓이 되어 승리 판정과 라운드 진행이 둘 다 정지한다.
현재 미발현 이유: 웨이브별 스폰 소요(5/5/7.5/10/15초) < duration 30초. 물량이나 간격을 키우는 순간 발현한다 — 페이싱 튜닝보다 반드시 먼저 수정해야 한다.

5. 설계 원칙 — 컨벤션 정렬

§3-4 수정안을 정할 때, 프로젝트 안에 이미 같은 종류의 버그를 막아둔 선례가 두 건 있다. 새 패턴을 만들지 않고 이 중 하나에 맞춘다.

레퍼런스위치차용 포인트
비동기 이탈 시 상태 복원 (try/finally) CardSelectionPresenter.cs:76-87 복원 지점이 한 곳. 성공·실패·취소 어느 경로로 빠져나가도 반드시 실행. 주석이 목적을 명시("soft-lock 방지")
취소를 예외 대신 반환값으로 (SuppressCancellationThrow) VfxPlayer.cs:86-91 try/catch 자체를 제거. 취소를 bool로 받아 정상 제어 흐름으로 처리
결합 결론: 컨벤션은 try/catch/finally 지양이나 "불가피한 정리는 최소 범위 허용"이다. 두 선례 중 VfxPlayer 방식이 catch를 없애 컨벤션에 더 가깝지만, 중첩 루프에서 복원 지점이 2곳으로 늘어난다 — 이번 버그의 원인이 바로 "복원 지점 누락"이므로, 단일 수정 원천 원칙에 따라 CardSelectionPresenter의 finally 방식을 권장한다.

레퍼런스 B — VfxPlayer (SuppressCancellationThrow)

Assets/Scripts/Systems/Abilities/Effects/VfxPlayer.cs:86-91
        private async UniTask ReturnAfterAsync(float seconds, CancellationToken token)
        {
            bool canceled = await UniTask.Delay(System.TimeSpan.FromSeconds(seconds),
                cancellationToken: token).SuppressCancellationThrow();

복원 지점을 finally 한 곳으로 모은다. 취소 시에는 CheckWaveComplete()를 건너뛰는 기존 의미를 그대로 유지한다.
