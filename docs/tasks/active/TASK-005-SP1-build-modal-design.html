Grid 타워 빌드 모달 (SP1) — 슬롯 선택·강조 + 구매 설치 설계

설계 제안서 검토 대기 TASK-005 B · 풀 모달 분해 1/3 · 2026-06-09

1. 제보 요지

"TowerPlacementController 가 완성일리가 없는데? 선택한 위치에 어떤 타워를 두거나 업그레이드 할지에 대한 시스템이나 UI도 없고, 눌렀을 때 해당 타워 슬롯을 강조하는 효과도 안 만들었는데?"

앞서 "코드 완성"이라고 보고한 것은 과장이었음을 인정하고, 실제 배치 UX(슬롯 강조 → 타워 선택/구매 모달 → 설치)를 정식 설계한다.

핵심: 현재 TowerPlacementController 는 클릭 → 하드코딩 단일 타워 즉시 설치인 P0 스텁뿐. 선택·강조·구매 UI가 전무하다. SP1 은 빈 슬롯에 한해 강조 + 빌드 모달을 도입한다.

2. 현재 동작 (재현 경로)

  1. GridScene 플레이 중 빈 타워 슬롯 좌클릭
  2. TowerPlacementController.cs:68-74 OnClick() 가 곧바로 TryPlace(CurrentCell()) 호출
  3. TowerPlacementController.cs:92-111 TryPlace() 가 TowerSlot 검증 → 점유 검사 → economy.TrySpend(cost) → 직렬화된 단일 towerData 를 즉시 생성
  4. 슬롯 강조도, 어떤 타워를 둘지 선택할 UI도 없이 한 번의 클릭으로 종료
즉 "입력 감지 + 설치"가 한 경로에 직결되어 있어, 사용자가 원하는 선택·강조·구매 단계가 끼어들 여지가 구조적으로 없다.

3. 근본 원인

Assets/Scripts/Systems/Tower/TowerPlacementController.cs · OnClick / TryPlace L68-111
private void OnClick(InputAction.CallbackContext ctx)
{
    if (mapData == null || towerData == null || economy == null) return;
    if (pointAction == null || targetCamera == null) return;

    TryPlace(CurrentCell());   // ← 클릭 즉시 설치, 선택/모달 단계 없음
}

private void TryPlace(Vector2Int cell)
{
    if (mapData.GetCellType(cell.x, cell.y) != CellType.TowerSlot) return;
    if (occupied.ContainsKey(cell)) return;
    if (!economy.TrySpend(towerData.cost)) return;

    GameObject go = Instantiate(towerData.prefab, ...);   // ← 단일 타워 종류 하드코딩
    ...
}

두 가지 구조적 한계: ① 입력→설치 직결로 선택·강조·구매 UI가 들어설 자리가 없다. ② towerData 단일 직렬화 필드라 "어떤 타워를 둘지"라는 개념 자체가 부재하다. SP1 은 이 경로를 "슬롯 선택(이벤트) ↔ 설치(메서드)" 로 분리한다.

4. 기획 요구사항 (사용자 확정)

  • 목표 = 원작 풀 모달: 빈 슬롯 클릭 → 타워 선택/구매 모달 → 설치, 기존 타워 클릭 → 업그레이드 모달
  • 한 스펙에 다 담기엔 커서 3개 서브프로젝트로 분해 합의 — SP1(빌드 모달), SP2(관리 모달: 업그레이드·판매), SP3(로스터 확장·밸런싱)
  • "SP1 부터 할게" — 이번 범위는 빈 슬롯 강조 + 타워 선택·구매·설치까지. 업그레이드·판매는 SP2 로 제외
  • 슬롯 클릭 시 해당 슬롯 강조 효과 포함

5. 설계 원칙 — 컨벤션 정렬

통일감 있는 구현을 위해 프로젝트 내 두 레퍼런스의 사상을 결합한다.

레퍼런스위치차용 포인트
HUD MVP UIRoot.cs · Inject() L31-39 View / Presenter / Model 분리 — UIRoot 가 도메인 모델을 주입해 Presenter 를 한 줄로 조립. 빌드 모달도 동일 패턴으로 합류
합성 루트 주입 GameManager.cs · CreateMode() L97-108 · ModeContext.cs 의존성을 ModeContext 로 묶어 모드별로 주입. 게임플레이↔UI 연결도 이 주입 흐름에 얹음
결합 결론: 모달은 HUD 와 동일한 MVP(View+Presenter)로 만들어 UIRoot.Inject 한 줄로 합류시키고, 게임플레이 측 TowerPlacementController 와 UI 측 Presenter 의 연결은 합성 루트 주입 경로(ModeBootstrap → GameManager → UIRoot)를 그대로 따른다.

8. 검증 시나리오

UI·입력 중심이라 PlayMode 수동 검증을 우선한다. (Presenter 로직은 SP2 에서 시임 분리 시 EditMode 화 재검토)

#시나리오기대 동작
1빈 슬롯 좌클릭슬롯 강조 + 빌드 모달 오픈, 즉시 설치 안 됨
2모달에서 살 수 있는 타워 선택골드 차감 + 해당 슬롯에 설치 + 모달 닫힘
3골드 부족 타워버튼 비활성, 설치 불가
4모달 열린 채 바깥/다른 빈 슬롯 클릭닫힘·강조 해제 / 새 슬롯으로 전환
5점유 슬롯 클릭강조만 (관리 모달은 SP2)
6Arena 씬 진입빌드 모달 없음, 기존 동작 유지
