Arena A2 — 코어 자동전투(능력 실행) 설계

설계 제안서 설계 확정 설계 확정 · 2026-06-16 · TASK-012 (A1 후속) · 풀링은 TASK-013 분리

1. 제보 요지

"코어 자동 전투로 넘어가자." A1에서 능력 데이터 골격만 구축됐고 실제 능력·전투 연결이 없다. A2는 코어가 능력으로 자동 전투하도록 실행 시스템 + 스타터 능력을 만든다.

핵심: 능력 종류를 서브클래스로 가르지 않고, 단일 Tick + 합성(쿨다운 헬퍼 / 상시 인터페이스)으로 조합한다. 시간축 거동(지속성)은 능력이 아니라 자가구동 효과 엔티티에 캡슐화한다.

2. 현재 동작 (재현 경로)

  1. A1: ActiveAbilityData.cs:16 의 abstract Execute(ctx, self) — 1회 발동만 표현(주석 "가동 루프는 A2")
  2. 중앙 타워 전투는 전부 DEBUG: TowerActor.cs:55-68 의 토글(single/aoe/projectile) → IAttackBehavior.Execute, CombatLogic.cs:30 단일 attackSpeed 게이트
  3. 데미지 경로: SingleTargetAttack.cs:15 target is IDamageable d → d.TakeDamage()
  4. 투사체: DebugProjectile.cs:22 자가 구동(이동·유도·관통)이나 매 발 CreatePrimitive+Destroy

3. 근본 원인

Assets/Reference/dot-defense-main/index.html · 능력 tick 모델
// 원작: 매 프레임 tick(ab) — 두 부류 혼재
nova.tick:    for(w of ab.waves) w.r += 5; ...   // 지속(매 프레임 상태 갱신)
shot.tick:    if(--ab.cooldown>0) return; fire() // 이산(쿨다운 발동)
orbital.tick: ab.angle += rotSpeed; ...          // 지속(상시 회전)

A1의 Execute(1회)만으로는 지속형(노바·오비탈)을 표현할 수 없다. 또한 이산/지속을 상호배타 서브클래스로 가르면 "둘 다 가진 능력"(터렛=상시 소환+주기 발사)에서 단일 상속이 막힌다.

4. 기획 요구사항 (사용자 확정)

  • 추상화를 완벽히 잡고, 원작 종류(아키타입)마다 디폴트 템플릿 1개씩. 나머지는 추후 원작에 맞춤.
  • 합성 기반: 상위 단일 Tick + 쿨다운 헬퍼 + IAbilityLifecycle 인터페이스 → 한 능력이 쿨다운+상시 동시 보유 가능 (사용자 지적 반영).
  • A2 범위: 추상화 + 러너 + 코어 배선 + 2 파운데이션(샷=이산, 오비탈=상시). 나머지 4종류 추후.
  • 풀링은 TASK-013 분리 (현재 범용 풀 없음). A2는 교체 심만 두고 단순 구현.
  • VFX는 ExternalResources/Hovl Studio 조합 검토·결정 (직접 제작 X).

6. 해결 방안 — 변경 사항

(1) ActiveAbilityData — Execute→Tick + 쿨다운 헬퍼 수정 필요

Assets/Scripts/Systems/Abilities/ActiveAbilityData.cs
▼ BEFORE (A1)
public abstract class ActiveAbilityData : AbilityData {
    public float baseCooldown = 1f;
    // 1회 발동(투사체·데미지 등). 가동 루프는 A2.
    public abstract void Execute(in AbilityContext ctx, AbilityInstance self);
}
▼ AFTER
public abstract class ActiveAbilityData : AbilityData {
    public float baseCooldown = 1f;
    public abstract void Tick(in AbilityContext ctx, AbilityInstance self, float dt);
    protected bool TickCooldown(AbilityInstance self, float dt)        // 감소·준비여부(리셋 X)
        { self.cooldownRemaining -= dt; return self.cooldownRemaining <= 0f; }
    protected void ResetCooldown(AbilityInstance self, in AbilityContext ctx)  // 발동 성공 후
        { self.cooldownRemaining = Mathf.Max(0.05f, CooldownAtLevel(self.level) - ctx.Modifiers.cooldownReduction); }
}
// 상시 수명만 구현 (러너가 add/remove 시 호출)
public interface IAbilityLifecycle { void OnEquip(in AbilityContext, AbilityInstance); void OnUnequip(in AbilityContext, AbilityInstance); }

핵심 변경 포인트

  • Execute(1회) → Tick(매 프레임) — 이산/지속 모두 수용
  • 쿨다운은 헬퍼 2분리: TickCooldown(준비여부) + ResetCooldown(발동 후) → 타겟 없으면 준비 유지(원작 충실)
  • 상시 수명은 별도 인터페이스 IAbilityLifecycle — 서브클래스 강제 없이 조합
  • AbilityInstance에 object runtimeState, AbilityContext에 IEffectSpawner Effects 추가

(2) 효과 엔티티 레이어 — 자가구동 + 풀링 심 수정 필요

Assets/Scripts/Systems/Abilities/Effects/*.cs (신규)
abstract class AbilityEffect : MonoBehaviour, IPoolable {
    protected IEffectSpawner spawner; public void Bind(IEffectSpawner s){ spawner = s; }
    protected void Release() => spawner.Release(this);   // Destroy 대신 (풀링 심)
}
interface IEffectSpawner { T Spawn<T>(T prefab) where T : AbilityEffect; void Release(AbilityEffect fx); }

// A2 구현 2종 (Hovl 프리팹 비주얼 + 우리 로직)
class ProjectileEffect : AbilityEffect  // DebugProjectile 승격: 유도·이동·관통·TakeDamage, 소진 시 Release
class OrbiterSetEffect : AbilityEffect  // 회전·반경추종·접촉 데미지(재타격 Map), OnUnequip서 Release
풀링 구현(IEffectSpawner의 풀 버전)은 TASK-013. A2는 SimpleEffectSpawner(Instantiate/Destroy)로 시작 → 무수정 교체.

(4) 디버그 공격계 — 코어 경로 미사용 Grid 잔존

IAttackBehavior·DebugProjectile·AttackContext·TowerActor 토글은 코어 경로에서 쓰지 않는다. Grid 배치 타워는 이 경로를 유지하므로 제거하지 않는다(Grid 실타워 도입 시 별도 정리).
