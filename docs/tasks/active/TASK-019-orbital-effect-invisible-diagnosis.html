오비탈 이펙트 미표시 진단 — 위치 문제가 아니라 "이펙트 자체가 안 그려지는" 문제

원인 분석 수정안 제시 분석 완료 · 2026-07-15

1. 제보 요지

"지금 오비탈 능력의 이펙트가 안 보이던데, 이펙트 위치 문제인지 아니면 이펙트 자체가 안 보이는 문제인지 진단해봐."

결론: 위치 문제가 아니다. 위성(오브)은 카메라 화면 안에 있고 렌더러도 켜져 있으나, 오브의 주 비주얼이 화면에 유의미한 픽셀을 전혀 그리지 않는다 — 즉 "이펙트 자체가 안 보이는" 문제다. 원인은 프리팹 구성 결함(월드 시뮬레이션 공간 + 본체 머티리얼 NULL)이 핵심이며, 최대 반경 고정은 부차적 악화 요인이다.

2. 현재 동작 (재현 경로)

  1. 아레나 모드 진입 → ArenaModeBootstrap.cs:99-100 이 코어 능력 예열 후 스타터 장착
  2. 오비탈 장착 시 OrbitalAbilityData.cs:29-33 OnEquip() 가 OrbiterSetEffect 를 스폰하고 Activate(ctx.Origin, ...) 호출
  3. OrbiterSetEffect.cs:39-60 EnsureOrbs() 가 OrbVisual_CyanBlue 프리팹을 위성 수만큼 자식으로 생성
  4. OrbiterSetEffect.cs:64-87 Update() 가 매 프레임 orbs[i].position = center + (cos, 0, sin) * radius 로 위성을 XZ 궤도에 배치
  5. 런타임 확인: 위성 2개가 active·화면 안(viewport 0.47~0.52, 0.41~0.69)·isVisible=True·머티리얼 유효인데도 화면에 오브가 보이지 않음

3. 근본 원인

가시성 판정 3요소(화면 안 · 렌더러 켜짐 · 머티리얼 유효)가 모두 정상이므로 "카메라 밖" 위치 문제가 아니다. 실제 원인은 이펙트 내부 구성에 있다.

원인 A — 위성 본체 파티클의 머티리얼이 NULL (프리팹)

Assets/Prefabs/Abilities/OrbVisual_CyanBlue.prefab · 루트 ParticleSystem
// 런타임 조회 결과 (파티클 4개 중 루트)
PS:OrbVisual_CyanBlue  mat=NULL  startColorA=0.40  simSpace=World
PS:Sparkle             mat=Flare6cg      startSize=0.04  simSpace=World
PS:Head (1)            mat=CommonWhite    startSize=0.7   simSpace=Local
PS:Fire                mat=CommonFire     startColorA=0.176 simSpace=World

오브의 주 비주얼(청록 본체)을 담당하는 루트 파티클의 렌더러 머티리얼이 NULL → 본체가 아무것도 그리지 않는다. 전체 화면 픽셀 스캔에서 밝은 청록 픽셀 0, 밝은 흰색 픽셀 0 으로 이를 확인했다.

원인 B — 파티클 4개 중 3개가 World 시뮬레이션 공간 (프리팹 × 코드)

Assets/Scripts/Systems/Abilities/Effects/OrbiterSetEffect.cs · Update() L78-86
for (int i = 0; i < orbs.Count; i++)
{
    if (!orbs[i].gameObject.activeSelf) continue;
    float a = angle + (Mathf.PI * 2f / Mathf.Max(1, active)) * idx;
    Vector3 pos = center + new Vector3(Mathf.Cos(a), 0f, Mathf.Sin(a)) * radius;
    orbs[i].position = pos;   // 매 프레임 이미터를 순간이동
    DamageAround(pos);
    idx++;
}

위성 이미터는 매 프레임 반경 12를 ~24u/s 로 도는데, 파티클 3개(루트·Sparkle·Fire)가 World 공간이라 방출된 파티클이 이미터를 따라오지 못하고 궤도 뒤로 흩뿌려진다. 측정된 파티클 bounds 가 10~15유닛 으로 번져 있어, "뭉친 밝은 오브"가 아예 형성되지 않는다. 이미터를 따라오는 건 Head(Local 공간) 뿐인데 흰색 1개·크기 0.7 로 시각적 존재감이 없다.

원인 C(부차) — 반경이 최대(12)로 고정, 궤도가 지면(Y≈0)에 붙음 (코드)

Assets/Scripts/Systems/Abilities/Effects/OrbiterSetEffect.cs · Update() L69-71

반경을 "최근접 적까지의 거리"로 추종하므로, 적이 멀면 반경이 maxRadius(12) 로 커져 위성이 아레나 가장자리 지면에 붙는다. 궤도 평면은 center.Y(=0), 적/비주얼은 enemyHeight(0.8) → 위성이 잔디에 스치듯 깔려 40° 부감 카메라에서 더 놓치기 쉽다. (이는 미표시의 직접 원인은 아니고 악화 요인.)

4. 확정 필요 사항 (사용자 판단 대기)

원인 A·B 는 명백한 결함이라 사용자 판단 없이 수정 가능하나, 원인 C 는 기획 의도에 따른 설계 결정이라 확정이 필요하다.

  • 궤도 반경 정책: 현행 "최근접 적 거리 추종(1.5~12)"을 유지할지, 아니면 코어 곁을 도는 고정/소형 반경으로 바꿀지 — 메모리상 오비탈은 "코어 주위 궤도 공격"으로 정의됨.
  • 궤도 높이(Y): 위성을 적 높이(enemyHeight)로 띄워 지면에서 분리할지 — 현재 Y=0 은 시각적 문제이자 잠재적 타격 판정 문제(§7 참조).
  • 비주얼 크기/알파 상향 여부: 게임플레이 거리(카메라 ~60u)에서 읽히도록 파티클 크기·알파를 키울지 (에셋 튜닝).

5. 설계 원칙 — 컨벤션 정렬

같은 AbilityEffect 계열의 정상 동작 효과 2건과 비교하면, 공통 사상은 "비주얼을 이동하는 이펙트 트랜스폼에 붙여 함께 움직인다" 이다. 오비탈만 이 사상에서 이탈해 있다.

레퍼런스위치차용 포인트
AreaZoneEffect AreaZoneEffect.cs:32-39 비주얼을 자식으로 붙이고 localPosition=0 유지 — 존이 이동해도 비주얼이 트랜스폼에 고정되어 함께 움직임
ProjectileEffect ProjectileEffect.cs:42-48 트랜스폼 자체를 이동시키고 자식 파티클이 Local 로 따라옴 — 명시 PlayVisuals() 로 재생 보장
결합 결론: 이동하는 이펙트의 비주얼은 Local 시뮬레이션 공간으로 트랜스폼에 종속시켜야 "뭉친 채로 함께 이동"한다. 오비탈은 위성 트랜스폼을 빠르게 이동시키면서 파티클을 World 로 둬 두 레퍼런스의 사상을 어겼다.

레퍼런스 ① AreaZoneEffect — 비주얼 자식 고정

비주얼이 존 트랜스폼에 localPosition=0 으로 붙어, 존 중심이 곧 비주얼 중심이 된다. 흩어짐이 없다.

레퍼런스 ② ProjectileEffect — 트랜스폼 이동 + 파티클 추종

Assets/Scripts/Systems/Abilities/Effects/ProjectileEffect.cs · PlayVisuals() L42-48
private void PlayVisuals()
{
    ParticleSystem[] systems = GetComponentsInChildren<ParticleSystem>(true);
    for (int i = 0; i < systems.Length; i++)
        if (systems[i].main.playOnAwake) { systems[i].Clear(true); systems[i].Play(true); }
}

투사체는 트랜스폼째로 이동하고 파티클이 함께 따라온다(Local). 재사용/재발사 시에도 명시 재생으로 비주얼을 보장한다.

핵심 변경 포인트

  • World → Local: 이동하는 위성에 파티클이 종속되어 뭉친 오브로 함께 이동 (원인 B 해소).
  • 루트 머티리얼 지정 또는 루트 이미터 제거: 본체가 실제로 그려지게 함. NULL 이미터가 불필요하면 삭제가 더 깔끔 (원인 A 해소).
  • 크기·알파 상향: 게임플레이 거리에서 읽히도록 (에셋 튜닝, 실제 값은 인게임 확인 후 조정).
프리팹 에셋 변경이라 코드 diff 가 아닌 컴포넌트 속성 변경이다. 값 튜닝은 §8 검증에서 인게임으로 확정한다.

7. 영향 범위 및 부수 효과

항목분석
프리팹 World→Local 전환 렌더 로직에 안전. 파티클이 위성 트랜스폼에 종속될 뿐, 타격 판정(DamageAround)은 트랜스폼 좌표 기반이라 무관
루트 이미터 제거 시 주의: VfxPlayer.EnsurePlay 가 자식 파티클을 캐시하므로 루트 제거해도 재생은 유지되나, 프리팹에서 참조 잔재 없는지 확인 필요
궤도 높이 Y=0 → enemyHeight 잠재 타격 버그 동반: 현재 위성 Y=0, 적 Y=0.8, hitRadius=0.6 → 수직 거리(0.8) > 반경(0.6) 이면 3D 거리 판정에서 적을 아예 못 때릴 수 있음. 높이 상승은 가시성과 타격을 함께 개선
반경 고정 전환 게임플레이 변화: 적 추종 광역 → 코어 근접 방어로 능력 성격이 바뀜. 기획 확정 필요
다른 능력/이펙트 영향 없음. 변경은 오비탈 전용 프리팹·클래스에 한정

8. 검증 시나리오

가시성은 인게임 육안 확인이 필요(파티클 렌더는 자동 테스트 부적합). MCP 비포커스 캡처는 플레이 루프 정지(dt=0)로 신뢰도가 낮으므로, Recorder 녹화(Game View 리페인트 강제) 로 확인한다.

#시나리오기대 동작
1 회귀 핵심 — World→Local + 루트 머티리얼 수정 후 오비탈 장착 뭉친 청록 오브가 위성 위치에 보이며 함께 회전
2 적이 없을 때 / 멀리 있을 때 궤도 반경 확정된 반경 정책대로 (고정 시 코어 곁 유지)
3 궤도 높이 상승 후 근접 적 타격 위성이 적과 접촉 시 데미지 적용 (수직 거리 버그 해소 확인)
4 위성 수 증가(레벨업) 시 다중 오브 각 오브가 개별 가시·회전
5 능력 해제(Unequip) 후 반납 오브·파티클 정리, 잔상 없음
