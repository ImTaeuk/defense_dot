Arena HUD 통합 설계 — 기능형 라운드 타이머 + 점수 데이터

설계 제안서 설계 확정 설계 확정 · 2026-06-14 · TASK-012 후속

1. 제보 요지

새로 제작한 ArenaHUD_Panel.prefab(라운드/시간/골드/점수/적 + 시간바·적바)을 데이터 파이프라인에 통합한다. "새 HUD를 만들었는데 왜 전혀 라운드나 시간, 골드 점수 등이 반영이 안 되지?"

핵심: 라운드·골드·적은 기존 모델로 즉시 공급 가능하나, 시간·점수는 백킹 데이터가 없어 신규 모델이 필요하고, 시간은 단순 표시가 아니라 라운드 진행 루프와 직결된 결정이다.

2. 현재 동작 (재현 경로)

  1. 씬 시작 → GameManager.cs:88-89 가 UIRoot.Inject(...) 호출
  2. UIRoot.cs:32 가 항상 HUDPresenter(hudView, ...) 생성 — 새 패널이 아니라 옛 Panel_Grid를 가리킴
  3. 새 ArenaHUD_Panel은 순수 비주얼 프리팹 — MVP 컴포넌트가 없어 어떤 모델도 구독하지 않음
  4. Arena 웨이브 루프는 EnemySpawner.cs:97-98 에서 스폰 완료 후 DelayedNextWaveAsync()(2초) 로 다음 웨이브 — 타이머 없음
  5. 시간·점수 백킹 모델 부재 → HUD의 시간·점수 칸을 채울 데이터 자체가 없음

3. 근본 원인

Assets/Scripts/UI/Views/RoundView.cs · EnemyCountView.cs (포맷 불일치)
// 기존 하위뷰는 라벨+값을 한 문자열로 출력
roundText.text = $"라운드 {current}/{total}";   // 풀스트링
countText.text = $"잔여 적 {alive} / {capacity}"; // 풀스트링

세 가지 원인이 겹친다. (1) 포맷 불일치 — 기존 하위뷰는 풀스트링을 쓰므로 label/value 분리 패널에 재사용하면 라벨이 중복된다. (2) 배선 부재 — UIRoot가 새 패널을 가리키지 않고, 패널엔 MVP 컴포넌트가 없다. (3) 데이터 부재 — 시간·점수를 보유·통지하는 도메인 모델이 없고, Arena 루프엔 라운드 타이머 개념 자체가 없다.

4. 기획 요구사항 (사용자 확정)

  • 타이머 = 기능형(원작 충실) — 라운드별 제한시간(WaveData.duration). 만료 시 적이 남아도 다음 웨이브 자동 진행, 조기 전멸 시 시간보너스 점수. (원작 index.html:20951-20967, duration :15737)
  • 점수 = 처치 + 시간보너스 — 처치당 10 × 라운드(원작 :19589), 조기 클리어 시 floor(절약시간 × 10 × 라운드)(원작 :20954). 메타 배수(asc/metaMods/행운)는 A7 메타 레이어로 제외. 인-런 표시 전용. 처치·시간보너스는 웨이브별 배율(killScoreMultiplier·timeBonusMultiplier, 기본 1)로 분리 가중 — 원작 단일 factor에서의 의도적 진화.
  • 아키텍처 = 접근 1 — 전용 Arena HUD 스택 + 스포너=라운드 러너 + 순수 모델 2개. Grid HUD·A0 구조 무수정.

통일감 있는 구현을 위해 프로젝트 내 두 레퍼런스에서 공통 사상을 추출했다.

레퍼런스위치차용 포인트
HUDPresenter (MVP) HUDPresenter.cs:11-55 구독은 Initialize / 해제는 Dispose — BasePresenter<TView,TModel> + IPresenter 패턴을 그대로 따른다
모드 플래그 분기 (A0) EnemySpawner.cs:97, GridDefenseMode.cs:53 WinsOnWaveClear 한 플래그로 Arena/Grid 분기 — 타이머·점수도 이 플래그로 Arena 한정

public override void Initialize() {

6. 해결 방안 — 변경 사항

(1) EnemySpawner — Arena 루프를 타이머 구동으로 재구성 수정 필요

private async UniTask SpawnWaveRoutineAsync(WaveData wave)
{
    isSpawning = true;
    foreach (var entry in wave.entries) { /* 스폰 */ }
    isSpawning = false;
    if (mode != null && !mode.WinsOnWaveClear)

}
▼ AFTER
void StartWave(int index) {
    currentWaveIndex = index;
    waveModel.SetWave(index + 1, count);
    timer.StartWave(wave.duration);        // ★ 라운드 타이머 시작
    waveCts?.Cancel();                      // 이전 스폰 취소(웨이브별 CTS)
    SpawnWaveRoutineAsync(wave).Forget();   // 다음 웨이브로 체이닝 X
}
public void TickRound(float dt) {          // ★ GameManager가 매 플레이 프레임 호출
    if (Grid || allWavesSpawned) return;
    timer.Tick(dt);
    if (timer.IsExpired) AdvanceRound(earlyClear: false);
}
void AdvanceRound(bool earlyClear) {
    if (earlyClear) score.AddTimeBonus(timer.Remaining, currentWaveIndex + 1);
    int next = currentWaveIndex + 1;
    if (next >= count) { allWavesSpawned = true; CheckWaveComplete(); }
    else StartWave(next);
}

핵심 변경 포인트

  • 라운드 진행 트리거를 "스폰 완료 + 2초"에서 "타이머 만료 OR 조기 전멸"로 교체
  • 처치 시 score.AddKillScore(currentWaveIndex + 1), 조기 전멸 시 score.AddTimeBonus(...) 가산 (Arena 한정)
  • 타이머가 스폰 중 만료되면 웨이브별 CTS 취소로 남은 스폰 폐기 (원작 advanceRound와 동일)
  • Grid 경로(WinsOnWaveClear == true)는 무수정 — TickRound 내부 가드로 통과

(2) UIRoot — 폴리모픽 단일 HudRoot 합성 (모드 무지) 수정 필요
