1. 요지 — 두 설계 원칙

사용자 원칙: 흩어지고 직관적이지 못한 설계를 배제한다.

  • 규칙 1 — 단일 수정 원천: 기능을 수정할 것이면 그 기능의 수정 원천이 단 한 곳이어야 하고 바로 알 수 있어야 한다.
  • 규칙 2 — 데이터 원천 직접 접근: 기능을 추가할 것이면 데이터 원천을 바로 알 수 있어야 하며 그 원천에 바로 접근 가능해야 한다.
기존 합성 구조는 두 규칙을 모두 위반했다. 이번 리팩토링으로 합성의 모든 규칙과 데이터를 FusionService 한 집에 모았다.

3. 통합 구조 (After) — FusionService 단일 집

FusionService가 계보 데이터를 직접 소유하고, 판정·생성·배제·원자적 적용을 모두 담당한다. 나머지 코드는 호출만 한다.

Assets/Scripts/Systems/Cards/FusionService.cs (신규)
public sealed class FusionService
{
    private readonly FusionRecipeSet lineage;   // 데이터 원천 직접 소유
    public FusionService(FusionRecipeSet lineage) { this.lineage = lineage; }

    public void CollectOffers(AbilityLoadout lo, List<CardChoice> into, int max) // 판정+카드 생성
    public bool IsResult(AbilityData data)                                        // 일반 풀 배제 판정
    public void Apply(IAbilityCommandTarget core, CardChoice choice)              // 원자적 적용(재검증)
}
합성 수정 → FusionService만 편집(규칙 1). 합성 데이터 → FusionService가 직접 보유(규칙 2). DI는 ctx.Fusion 하나로 접근.
