TASK-005 타워 배치 시스템 — SP1 완료 요약

진행 요약 SP1 완료 (미커밋) PlayMode 검증 완료 · 2026-06-10

1. 개요 & 현재 위치

TASK-005 는 원작 dot-defense 의 모드별 타워 등장·배치를 정식 구현하는 작업이다. Arena = 중앙 단일 타워, Grid = 슬롯 클릭 배치. "풀 모달"이 커서 3개 서브프로젝트로 분해했고, 이번 세션은 그중 SP1(Grid 슬롯 선택·강조 + 빌드 모달 구매·설치) 를 완성했다.

현재: A-1(Arena 중앙 타워) 커밋 완료, SP1(Grid 빌드 모달) 구현·검증 완료(미커밋). 다음은 SP1 커밋 후 다음 TASK 선정.

2. 완료 동작 (현재 플레이 가능)

  • Arena 모드 — 시작 시 중앙에 타워 1개 자동 배치, 사거리=맵 전체로 공전 적 공격 (ArenaModeBootstrap, 커밋 4ee53a8e/26a9db17)
  • Grid 모드 (SP1) — 빈 타워 슬롯 좌클릭 → 슬롯 강조 + 화면 하단 가로 카드 모달 → 타워(Tower Test/Sniper/Cannon) 선택 → 골드 차감·설치 → 모달 닫힘. 골드 부족 버튼 비활성, 점유 슬롯은 강조만, Arena 엔 모달 미생성.
SP1 흐름은 PlayMode 실증 완료 — 클릭→모달→구매→설치·차감 확인됨.

3. SP1 아키텍처 — 핵심 리팩토링

기존 TowerPlacementController 는 "클릭 시 하드코딩 단일 타워 즉시 설치"하는 P0 스텁이었다. 이를 "슬롯 선택(이벤트)"과 "설치(PlaceAt)"로 분리해, 그 사이에 빌드 모달(MVP)이 개입하게 했다.

Assets/Scripts/Systems/Tower/TowerPlacementController.cs
▼ BEFORE (P0 스텁)
private void OnClick(InputAction.CallbackContext ctx)
{
    TryPlace(CurrentCell());   // 클릭 즉시 단일 towerData 설치
}
▼ AFTER (선택/설치 분리)
private void OnClick(InputAction.CallbackContext ctx)
{
    if (EventSystem.current.IsPointerOverGameObject()) return;
    Vector2Int cell = CurrentCell();
    if (IsBuildableEmpty(cell)) Select(cell);   // 강조 + OnSlotSelected 발행
    else Deselect();
}
public bool PlaceAt(Vector2Int cell, TowerData data) { /* 순수 설치 */ }

빌드 모달은 기존 HUD 와 동일한 MVP 로 구성: TowerBuildModalView(uGUI) + TowerBuildPresenter + TowerRoster(SO). 게임플레이↔UI 연결은 ModeBootstrap.PlacementController 를 GameManager 가 UIRoot.Inject 로 전달하는 합성 루트 주입으로 처리(Arena 는 null → 모달 미생성).

4. 확정된 설계 결정

  • 방향 (가): SP1 은 "건설 파이프라인 토대". 원작의 가챠(3장 카드 뽑기)·능력(ability) 방식은 TASK-005 C(Skill 시스템)로 이월 — 파이프라인이 같아 나중에 모달 내용만 교체.
  • UI 원작화: 중앙 패널 → 화면 하단 가로 카드 바로 리모델 (원작 tdTowerModal 의 bottom 정렬 차용).
  • 이벤트 컨벤션: event 는 On*, 구독 핸들러는 Handle* (CLAUDE.md 코딩 컨벤션에 추가).
  • 구조: UIRoot 가 0-사이즈라 하단 바 stretch 가 무너져, BuildModal 서브트리를 Canvas 직하로 이동·전체화면화 (HUD·참조 불변).

5. 설계 원칙 — 컨벤션 정렬

SP1 은 신규 패턴 없이 프로젝트의 두 기존 사상에 정렬했다.
