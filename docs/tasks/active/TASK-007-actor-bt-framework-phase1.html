Actor BT 프레임워크 — Phase 1 구현 보고서

구현 보고서 Phase 1 완료 구현·검증 완료 · 2026-06-10

1. 요지

Actor의 행동(AI)을 Behavior Tree로 구동하고 그 결과를 ActorState로 표현하여 애니메이션이 반영하는 단방향 파이프라인 설계 중, 그 토대인 Phase 1 — 순수 BT 프레임워크를 구현·검증 완료했다.

핵심: BT가 ActorState의 유일한 writer가 되도록 토대를 깔았다. 같은 프레임에 상태가 여러 곳에서 덮어써지던 구조(애니 깜빡임의 근본)를 차단한다.

2. 파이프라인 동작 (구동 흐름)

  1. ActorBehaviorTree.Update() (Phase 2) 가 자기 트리를 매 tick 평가
  2. 리프(ActionLeaf) 가 POCO(이동·전투)를 호출하고 actor.SetState(...) 로 상태 기록 — 유일 writer
  3. ActorBase.SetState 가 StateChanged 이벤트 발화 (기존 코드 재사용)
  4. ActorAnimatorBinder (Phase 3) 가 구독하여 Animator 파라미터(State/Direction) push
  5. AnimatorController 에셋이 전환 결정 — 프리팹별 교체 = 오버라이드
본 보고서 범위(Phase 1)는 1~2단계의 트리 엔진이다. 3~5단계(통합·연출)는 Phase 2/3.

3. 설계 핵심 — 반응형 단락 평가

Assets/Scripts/Systems/Actor/Sequence.cs · Evaluate()
public override NodeStatus Evaluate(Blackboard blackboard)
{
    // 반응형: 매 tick 처음부터
    for (int i = 0; i < children.Count; i++)
    {
        NodeStatus status = children[i].Evaluate(blackboard);
        if (status != NodeStatus.Success) return status;   // Success 외 즉시 중단
    }
    return NodeStatus.Success;
}

반응형(reactive): running 자식 인덱스를 기억하지 않고 매 tick 루트부터 재평가한다. 그 덕에 우선순위 급변(예: stun 진입)에 다음 tick 즉시 반응하고, 노드가 무상태라 풀링(IPoolable) 재사용 시 리셋 부담이 없다.

4. 기획 요구사항 (사용자 확정)

  • 풀 BT 프레임워크를 구축 (스텁 → 정식 트리 엔진)
  • 트리는 코드 조립, 구체화된 Actor는 BuildPrimary() 오버라이드로 확장
  • Enemy는 비공격(이동만)이 베이스, Tower가 공격을 추가 (정통 TD)
  • Animator 구동 컴포넌트명은 ActorAnimatorBinder, 두뇌 컴포넌트명은 ActorBehaviorTree (약어 회피·업계 표준)
  • Blackboard는 1급 통로로 미리 깔되 데이터는 target/stunTimer 씨앗만

public abstract class BTNode

▼ AFTER — 프레임워크 (8개 파일)
public abstract class BTNode
{
    public abstract NodeStatus Evaluate(Blackboard bb);   // 컨텍스트 관통
}

public sealed class Sequence : BTNode { ... }   // 단락 + 반응형
public sealed class Selector : BTNode { ... }
public sealed class ConditionLeaf : BTNode { Func<Blackboard,bool> }
public sealed class ActionLeaf    : BTNode { Func<Blackboard,NodeStatus> }
public static class BT { Selector / Sequence / Condition / Action }  // 빌더
public sealed class Blackboard { ITargetable target; float stunTimer; }

핵심 변경 포인트

  • Evaluate(Blackboard) — 컨텍스트가 트리를 관통(나중에 Blackboard 데이터 추가 시 시그니처 변경 0)
  • 람다 리프(ConditionLeaf/ActionLeaf) — 액션마다 클래스를 만들지 않고 POCO를 클로저
  • 정적 빌더 BT — 트리를 가독성 있게 코드 조립

7. 영향 범위 및 부수 효과

항목분석
기존 코드 영향없음. 스텁 MoveToTargetNode는 외부 미참조(grep 확인) — 순수 추가 + 스텁 삭제 1건

런타임 통합아직 없음. 트리는 Phase 2(ActorBehaviorTree)에서 액터에 연결됨
