1. 요청 요지

사용자 요청: "옥토패스 트래블러와 같은 화면 효과를 만들려면 어떻게 하는게 좋을까?" → 효과 분해 미리보기를 통해 4개 레이어 전부(①틸트시프트 ②블룸 ③색감+비네팅 ④픽셀 빌보드) 적용 = 풀 HD-2D 로 확정.

핵심 결론: HD-2D 는 카메라 리그 · 포스트FX · 빌보드 3개 독립 하위시스템의 합이며, 프로젝트가 아직 플레이스홀더 단계라 지금 도입하는 비용이 가장 싸다(버릴 기존 아트가 없음).

  5. 빌보드 개념 이미 존재: GridSelectionActor.cs:90-95 ("Sprite를 지면에 눕힘 / 정면을 보게 함")

3. 핵심 설계 과제

설계의 두 가지 핵심 난점은 ① 카메라 책임이 맵 생성기에 혼재되어 있다는 점과 ② "틸트시프트 ≠ 일반 DoF"라는 점이다.

Assets/Scripts/Systems/Grid/MapVisualizer.cs · FocusCameraOnMap() L62-87
// MapVisualizer(맵 타일 생성기) 안에 카메라 배치가 섞여 있음 — 책임 혼재
mainCam.transform.rotation = Quaternion.Euler(cameraPitch, cameraYaw, 0);
float diagonal = Mathf.Sqrt(mapW * mapW + mapH * mapH);
// ... orthographicSize / distance 계산 ...
mainCam.transform.position = mapCenter - mainCam.transform.forward * 50f;

이 로직은 (1) 1회성 배치라 "지속적으로 중앙을 본다"를 만족 못 하고, (2) 그리드 모드 전용이며, (3) Camera.main 을 직접 조작한다. 사용자 요구("중앙 주시 + 디자이너 조절 + 모드별 + 에디터·런타임")를 충족하려면 전용 리그로 승격·일반화해야 한다.

틸트시프트 ≠ DoF: 일반 DoF는 "거리" 기준 블러, 틸트시프트는 "화면 세로 위치" 기준 블러. 기운 카메라에서는 표준 DoF가 틸트시프트를 근사(Phase 2)하지만, 정밀 제어는 커스텀 Renderer Feature(Phase 4)가 필요하다.

4. 기획 요구사항 (사용자 확정)

  • 풀 HD-2D — ①틸트시프트 ②블룸 ③색감+비네팅 ④픽셀 빌보드 전부 적용
  • 스프라이트 — "손으로 그린 픽셀 아트" (정석 HD-2D, idle/이동/공격 애니메이션 필요)
  • 카메라 — 항상 맵 중앙을 주시. 기본 약한 기울기(15~30°)
  • 조절 — pitch/거리 등을 디자이너가 에디터·런타임 양쪽에서 조절, 맵 모드별로 상이
  • 구현 방향 — 권장안 🅱️(커스텀 Renderer Feature 하이브리드)를 단계적으로 진행(빌트인 MVP → 커스텀 정석)

6. 설계 적용 — 주요 코드 변경안

(1) ModeBootstrap.cs — 카메라·포스트FX 주입 추가 수정 필요

Assets/Scripts/Systems/Mode/ModeBootstrap.cs
▼ BEFORE
public abstract class ModeBootstrap : MonoBehaviour
{
    public abstract IGameMode CreateMode(ModeContext ctx);
    public abstract int EnemyDisplayCapacity { get; }
}
▼ AFTER
public abstract class ModeBootstrap : MonoBehaviour
{
    [SerializeField] protected CameraRigConfig cameraConfig;
    [SerializeField] protected VolumeProfile postFxProfile;
    [SerializeField] protected CenterFocusCameraRig cameraRig;
    [SerializeField] protected Volume globalVolume;

    public abstract IGameMode CreateMode(ModeContext ctx);
    public abstract int EnemyDisplayCapacity { get; }

    /// <summary> 카메라 리그 바인딩 + 모드별 포스트FX 프로파일 적용 </summary>
    protected void BindPresentation(in ModeContext ctx)
    {
        if (cameraRig != null) cameraRig.Bind(ctx.CoreCenter, cameraConfig);
        if (globalVolume != null && postFxProfile != null)
            globalVolume.profile = postFxProfile;
    }
}
  • 각 모드는 자기 CameraRigConfig + VolumeProfile 에셋을 꽂아 "모드별 룩"을 갖는다.
  • BindPresentation 은 널 가드로 감싸 비주얼 미설정 모드도 안전하게 동작.

8. 검증 시나리오

대부분 에디터·플레이 모드 수동 검증(렌더 결과는 자동화 어려움). 상태 이벤트는 EditMode 테스트 가능.

#시나리오기대 동작
1에디터에서 pitch 슬라이더 조절씬 카메라가 중앙 주시 유지하며 즉시 각도 변경
2런타임 중 rig.Pitch 변경카메라 각도 변경 · config 에셋 불변
3모드 전환(Arena ↔ Grid)카메라 config·Volume 프로파일이 모드별 교체
4적 80마리 스폰모든 스프라이트 카메라 정면 + 깊이 정렬 정상 · 프레임 저하 관찰
5적 상태 전환(이동→사망) + 풀 재스폰애니메이션 전환, 재스폰 시 idle 정상
6틸트시프트 focusWidth 조절선명 띠 폭 실시간 변화
