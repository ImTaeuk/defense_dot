계보 합성(Fusion) 시스템 — 스크립트별 정리

구조 개요 현행 반영 역할 · 이름 · 동작 · 2026-07-14

1. 개요

타워마다 합성 계보를 두고, 재료 능력 2개가 각각 MAX 레벨이며 결과가 미보유일 때 레벨업 카드에 합성 카드(Fusion 티어)를 제시한다. 선택 시 재료 2개를 소진하고 결과 능력을 부여한다.

설계 원칙: ① 합성 규칙은 한 집(FusionSystem)에만 · ② 데이터 원천(계보)은 그 집이 직접 소유 · ③ 이름은 동작 그대로(게임 어휘).

2. 데이터 흐름

계보 데이터 → 시스템 생성 → DI → UI → 위임
TowerData.fusionLineage        // 데이터 원천
   ↓ 구성 시점 노출
ArenaModeBootstrap.FusionLineage
   ↓ 합성 루트에서 생성
GameManager  →  new FusionSystem(lineage)
   ↓ 주입 (서비스만 노출, raw 계보는 UI에 안 감)
GameContext.Fusion

                                                         ↓ 모든 합성 규칙
                                                    FusionSystem  // 단일 원천

② 핵심 시스템 — 합성의 단일 원천

Assets/Scripts/Systems/Cards/FusionSystem.cs

역할: 합성의 단일 원천. 계보 데이터를 직접 소유하고 판정·카드 생성·결과 배제·원자적 적용을 모두 담당. 나머지 코드는 여기에 위임만 한다.

멤버동작
FusionSystem(FusionRecipeSet lineage)계보를 직접 소유(null이면 합성 비활성)
CollectOffers(loadout, into, max)재료 둘 다 보유+MAX & 결과 미보유인 레시피를 합성 카드로 만들어 목록에 채움(max 도달 시 중단)
IsResult(data)해당 능력이 계보 결과인지 판정(일반 카드 풀에서 배제용)
Apply(core, card)적용 직전 재검증(재료 재해석·MAX·결과 미보유) 후 원자적으로 재료 2개 소진→결과 부여
FindMaxed/Find는 내부 헬퍼(로드아웃에서 MAX 인스턴스 탐색).

5. 네이밍 원칙(이 시스템에 적용)

  • 동작 그대로 읽히게: 카드 모델은 "선택지(CardChoice)"가 아니라 능력에 동작을 적용하는 AbilityCard
  • 게임 어휘: 합성 단일 원천은 Repository/Service가 아니라 FusionSystem(CoreAbilitySystem과 짝)
  • 데이터 원천 직접 소유: 계보는 FusionSystem이 private로 직접 보유
